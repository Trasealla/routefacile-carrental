4. CARS / FLEET ENDPOINT                                            [EXTEND]
================================================================================

  Current shape (per item):
    {
      car_id,
      rate,
      car: { name, image }
    }

  Recommended extended shape:
    {
      car_id,
      display_order,            // sort order
      is_featured,              // highlight badge
      currency,                 // "AED"
      rate,                     // current default monthly rate
      original_rate,            // for strike-through pricing (optional)
      discount_badge,           // "20% OFF" / "Best Value" (optional)
      rate_by_duration: {       // price changes per term
        "1": 1800,
        "3": 1600,
        "6": 1450,
        "9": 1200
      },
      available_durations: [1, 3, 6, 9],
      mileage_per_month,        // 4000
      deposit_amount,           // 0 or override
      cta_label,                // override "Enquire Now" if needed
      car: {
        name,                   // "Mitsubishi Attrage"

================================================================================
7. ICON STRATEGY
================================================================================

  Frontend uses Font Awesome 6 (loaded globally in public/index.html).
  Backend should return the icon as a class string only:
      "fa-tag"  ->  rendered as  <i class="fa-solid fa-tag" />

  This keeps the CMS simple and avoids storing image files for icons.


================================================================================
8. LOCALIZATION (i18n)
================================================================================

  All text fields above must be returned in the requested language via
  the existing ?lang=en | ?lang=ar query parameter.

  Backend responsibility: store translations per locale in the CMS.
  Frontend responsibility: stop wrapping API-driven strings in t() to
  avoid double-translation.


================================================================================
9. FALLBACK BEHAVIOR
================================================================================

  Frontend will keep current hard-coded defaults as a safety net so the
  page never breaks if a CMS field is empty/missing.
